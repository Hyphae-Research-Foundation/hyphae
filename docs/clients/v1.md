# Public clients for API v1

Every client below consumes only the public `/v1` contract. None opens a data
directory, imports storage/query internals, or requires a database, model, or
embedding provider.

The TypeScript and Python manifests in this `0.2.1` source candidate are
source-only. This repository does not claim that either package is published
to npm or PyPI without separate registry evidence. Repository verification
checks generated-model synchronization, builds and unit-tests the TypeScript
source, compiles and unit-tests the Python source, and runs one live
conformance fixture across all five clients. The post-hardening `0.2.1` SDK
sources were also packed as a Python wheel/source distribution and real npm
tarballs; an isolated Python 3.11 environment installed the wheel without an
index, and an isolated Node consumer installed the SDK and integration
tarballs together offline and imported the SDK, Astro, Next, and Vite
surfaces. Those temporary worktree artifacts are not commit-bound publication
evidence, so the packages remain source-only and unpublished.

All five surfaces expose capabilities, KV, vector mutation, exact retrieval,
lexical-index definition, lexical retrieval, and hybrid retrieval. Rust,
TypeScript, Python, and remote CLI also expose liveness/readiness and verified
result/retrieval witness download. JSON clients use 60-second, 32 MiB response,
and 512 MiB witness defaults unless configured more strictly.

TypeScript and Python preserve exact signed 64-bit integers, reject invalid
JSON, validate stable error envelopes, and correlate error/header request IDs.
Their generated success models are static types, not runtime validators: a
syntactically valid but wrong-shaped successful payload can be returned to the
caller. This is an accepted source-only `0.2.1` residual, not a claim of full
wire-shape validation.

The TypeScript deadline starts before request serialization and races `fetch`
and every success, error, or witness body read. A custom `fetch` that ignores
`AbortSignal` cannot delay client rejection or provide a late accepted result,
but it may continue external work outside the SDK after rejection. The Python
deadline uses a per-request watchdog to shut down the active CPython socket
across headers and all body kinds. Operating-system DNS resolution occurs
before CPython exposes that socket and is not portably preemptible; an expired
request fails closed when resolution returns.

## Rust

```rust,no_run
use hyphae_client::HyphaeClient;
use hyphae_contracts::v1::GetRequestV1;

# async fn example() -> Result<(), Box<dyn std::error::Error>> {
let client = HyphaeClient::builder("http://127.0.0.1:8787")?.build()?;
let response = client.get(&GetRequestV1 { key_hex: "61".into() }).await?;
println!("found={} request={}", response.value.found, response.request_id);
# Ok(())
# }
```

The builder accepts an optional bearer token, complete timeout, JSON response
bound, and witness bound. See [embedding Rust](../embedding/rust.md#choose-a-crate)
for repository dependency policy.

## TypeScript

```typescript
import { HyphaeClient } from "@celiums/hyphae";

const client = new HyphaeClient("http://127.0.0.1:8787");
const response = await client.get({ key_hex: "61" });
console.log(response.value.found, response.requestId);
```

Hyphae transports signed 64-bit JSON integers. Values within JavaScript's safe
range are `number`; larger values are `bigint`. Sending an unsafe `number`
throws locally, so use `9223372036854775807n` when exact large values matter.

```bash
cd sdks/typescript
npm ci --ignore-scripts
npm test
```

The complete package guide is [`sdks/typescript/README.md`](../../sdks/typescript/README.md).

## Python

```python
from hyphae_sdk import HyphaeClient

client = HyphaeClient("http://127.0.0.1:8787")
response = client.get({"key_hex": "61"})
print(response.value["found"], response.request_id)
```

The Python package requires Python 3.11 or newer and has no runtime
dependencies. Python integers preserve the complete signed 64-bit domain.
The complete package guide is
[`sdks/python/README.md`](../../sdks/python/README.md).

## CLI

Request bodies are typed contract JSON read from a file or standard input.
Bearer secrets come from `HYPHAE_BEARER_TOKEN` or a restricted file, never an
argv value.

```bash
hyphae remote --base-url http://127.0.0.1:8787 capabilities
printf '%s' '{"key_hex":"61"}' |
  hyphae remote --base-url http://127.0.0.1:8787 get --request -
```

All fifteen remote commands print exact v1 success models. `witness` accepts a
`ProofV1` or structurally equivalent `RetrievalProofV1`, writes to a new path,
and refuses to replace an existing file. `hyphae verify-retrieval` performs
offline exact, lexical, and hybrid verification after artifact download.

## MCP

Configure an MCP host to spawn:

```json
{
  "command": "hyphae",
  "args": ["mcp", "--base-url", "http://127.0.0.1:8787"]
}
```

The stdio adapter implements stable MCP `2025-11-25` and exposes
`hyphae_capabilities`, `hyphae_put`, `hyphae_get`, `hyphae_delete`, and
`hyphae_query`, plus vector-space definition, vector put/delete, exact
retrieval, lexical-index definition, lexical retrieval, and hybrid retrieval.
Mutations remain subject to host/user authorization. The adapter does not
start a listener or access storage internals.
See the complete [MCP guide](../../mcp/README.md) for lifecycle, bounds, tool
schemas, errors, and host configuration.

## Conformance

After building the Rust binaries and TypeScript SDK:

```bash
cargo build -p hyphae-cli -p hyphae-conformance-rust --locked
(cd sdks/typescript && npm ci --ignore-scripts && npm run build)
python tools/run_conformance.py
```

Each consumer receives a fresh server and data directory. Success emits one
JSON summary containing all five clients.
