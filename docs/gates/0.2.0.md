# Hyphae 0.2.0 release gate

Status: historical published release; retained hosted closure evidence is
incomplete

The annotated `v0.2.0` tag peels to
`170380453a2ca6322a4c8bc50417318daee1c011`, and the matching
[GitHub release](https://github.com/celiumsai/hyphae/releases/tag/v0.2.0) is
published. All ten publishable Rust workspace crates are available at version
`0.2.0`. Those observable publication outcomes do not reconstruct the exact
hosted evidence that this historical gate required.

## Candidate scope

- Workspace and public package version: `0.2.0`.
- Disk format: `2`, with explicit format-1 migration.
- Public HTTP API major: `/v1`, additive retrieval contracts only.
- Retrieval semantics: exact vector v2, lexical v1, hybrid v1.
- Proof formats: existing `result-proof-v1` plus additive
  `retrieval-proof-v1`.

## Local evidence

- Rust format, clippy, workspace tests, rustdoc, and MSRV.
- Canonical contracts, generated assets, documentation examples, disk-format
  fixture, and retrieval golden synchronization.
- Rust, TypeScript, Python, remote CLI, and MCP conformance.
- Astro, Next, Vite, PliegoRS, and public-boundary checks.
- Dependency audit/deny, package-content audit, deterministic archive tests,
  native archive install smoke, load, restart/restore soak, and bounded fuzz.
- Retrieval latency, memory, write amplification, recovery, proof, and
  lifecycle measurements under [`evidence/`](evidence/).

The automated package-install smoke is the milestone flow: it runs one
installed binary, writes documents and vectors, executes exact, lexical, and
hybrid retrieval, downloads each witness, destroys the live-server dependency
for offline verification, verifies every retrieval proof, then requires the
same canonical retrieval outcomes and new offline-verifiable proofs after
compaction and again after backup/restore.

The restart/restore soak additionally leaves a valid batch Put request partially
streamed, kills the server while that write is still in flight, restarts the
same data directory, and requires the previously confirmed count and all three
retrieval modes to remain intact. Storage tests exhaustively cover every
incomplete transaction-log prefix; the soak covers the public single-binary
interruption and recovery path.
