## Patch scope

- Set the default offline result/retrieval policy to a 2 GiB snapshot-witness
  file and 1 GiB of aggregate decoded logical payload retained by the
  verifier across KV, vector-space/vector, and lexical-index payloads.
  Embedded callers may choose a different explicit policy.
- Set the default exact-vector replay policy, including the exact branch of
  hybrid replay, to 1 GiB of candidate key/vector bytes, and preflight count,
  bytes, and deadline before candidate allocation/materialization.
- Bound regular-file proof readers by caller/canonical byte ceilings and detect
  length changes. Carry the verification deadline through proof reads; retain
  the standalone byte-bounded decoder APIs without inventing a timeout
  parameter.
- Define the hybrid total deadline as lexical timeout plus exact-vector
  timeout, with both branches and fusion consuming that total. Include snapshot
  creation only in the bounded proof-producing facade path's remaining total;
  preserve the legacy proof method's stored maintenance behavior.
- Apply a fixed 256 MiB aggregate scanned-input ceiling to the standalone HTTP
  query route through additive bounded APIs, counting every inspected binary
  key plus exact canonical document bytes globally across pages/shards and
  including nonmatches. Preserve the `0.2.0` behavior of legacy Rust query
  entry points.
- Apply finite shared deadlines and aggregate byte/count ceilings to packaged
  CLI/server storage recovery and additive bounded embedded startup, snapshot,
  and compaction. Retain writer ceilings when an engine is opened under finite
  limits; preserve the `0.2.0` compatibility behavior of legacy embedded
  `open`.
- Preserve the separate 512 MiB server/client witness-download default.
- Return HTTP `413` `result_too_large` when direct witness admission exceeds
  its policy, and expose the route's `413` response in OpenAPI.
- Bound remote CLI request JSON at the default 4 MiB server request ceiling,
  proof JSON at the default 32 MiB response ceiling, and bearer-token
  file/environment input at 4,098 raw bytes. Preflight file lengths, read
  through `limit + 1`, and reject changed file lengths. Keep the fixed CLI
  ceilings explicitly non-negotiated from custom server capabilities.
- Make backup layout verification fail on the first unexpected entry without
  accumulating names, and copy only one opened regular source's captured
  length before rechecking it. Keep end-to-end elapsed-time bounding for
  complete `backup-verify`/restore as an explicit external operational
  responsibility, preserving compatibility.
- Carry reviewed dependency, pinned-action, and framework host-smoke
  maintenance accumulated after `v0.2.0`.
- Synchronize Rust crates, TypeScript/Python source packages, OpenAPI metadata,
  documentation, and package tests at product version `0.2.1`.
- Harden TypeScript/Python request deadline enforcement while preserving exact
  integers, invalid-JSON rejection, and runtime error/request-ID validation.
  Keep generated success models explicitly static-only; complete runtime
  success-shape validators are an accepted source-package residual.

This patch does not change API `/v1`, disk format `2`, exact-vector semantics
v2, lexical or hybrid semantics v1, `result-proof-v1`, or
`retrieval-proof-v1`.

The Rust compatibility design now preserves every `0.2.0` exhaustive error
enum and legacy method signature. Aggregate query-byte failures use separate
`BoundedQueryError`/`BoundedEngineQueryError` surfaces; finite storage-policy
failures remain typed in existing error source chains and are recoverable
through the documented accessors. The required artifact-bound
`cargo-semver-checks` comparison remains an unchecked final-candidate gate
below; this design resolution is not a claim that hosted release evidence
already exists.
