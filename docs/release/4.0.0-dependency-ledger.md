## Integration gates

The release remains blocked until one selected integration commit satisfies
all of the following:

1. Its ancestry or reviewed conflict-resolution patch contains every accepted
   lane input, and the ledger is replaced with that exact integration commit.
2. Catalog capability 4 and minor 8 are coherent across catalog, product,
   Rust wire, Python, and TypeScript, including fail-closed down-conversion.
3. Minor 9 carries the bounded embed-and-ingest operation end to end, with
   authorization, admission, transaction, response, and failure-path tests.
4. The offline CPU path remains the default. Any CUDA path is optional,
   reports its exact execution profile, and preserves the versioned fallback
   contract without weakening CPU authority.
5. Qwen-specific execution is claimed only if an exact model profile and its
   retained evidence are both present on the selected commit. Harness support
   alone is not a product profile or execution claim.
6. The complete package, SDK, conformance, security, and hosted release matrix
   passes on the selected commit, followed by a retained exact-SHA G8 closure.

## Crate publication

At the inspected release preparation head, `config/crates-io-release.json`
contains eight topological layers and exactly 24 publishable crates. The H100
lane package audit passed for those 24 packages at `4.0.0` and checked 42
compile-time assets. This is a local validation observation, not a publication
receipt or G8 evidence.

No new CPU or CUDA crate manifest was committed in the observed lanes, so the
release configuration does not speculate about package names or layers. If a
later selected tree adds a backend crate used by a published Hyphae package,
including through an optional dependency, that backend must itself be
publishable at exact version `4.0.0`, appear in an earlier dependency layer,
and increase `package_count`. A `publish = false` backend cannot be left as a
dependency of a registry package. If no new package is introduced, the count
may remain 24 after the package checker recomputes the complete publishable
workspace set.

The CPU implementation remains in the offline default. CUDA remains optional
and outside the default dependency graph. Publishing a CUDA Rust crate does
not authorize a CUDA-linked release artifact; license review, target-specific
validation, and an exact-source/device receipt remain separate gates.
