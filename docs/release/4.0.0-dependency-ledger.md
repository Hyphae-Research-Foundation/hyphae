## Source checks and open gates

1. The final candidate must contain selected Lane14 through merge ancestry;
   Lane14 records the Lane06 implementation through the reviewed cherry-pick.
2. Catalog capability 4 and minor 8 are coherent across catalog, product, Rust
   wire, Python, and TypeScript. Minor 9 adds bounded request tag 73 and response
   tag 47; minors 0 through 7 retain their historical encodings, and tag 69
   remains unknown.
3. Embedded, UDS, and native HTTP calls share the catalog-bound product
   dispatcher. It resolves target and profile from one snapshot, checks replay
   before inference, checks exact authority before inference and commit, and
   records document, vector, completion, and idempotency in one CSN. Local
   tests cover replay after reopen and backup/restore without an executor,
   revocation, corruption, executor failure, and no partial publication.
4. The default product remains offline and CPU-capable. The default-off CUDA
   feature selects a validated H100 and records the actual device, driver,
   runtime, BF16/FP16 compute, and canonical FP32 publication. An unavailable
   accelerator batch is discarded before a complete CPU retry when fallback
   is allowed. Generic CI hosts validate the non-CUDA feature set; the H100
   must pass the full all-features matrix.
5. The local artifact binds `Qwen/Qwen3-Embedding-0.6B` revision
   `97b0c614be4d77ee51c0cef4e5f07c00f9eb65b3` with `model.safetensors`
   SHA-256 `0437e45c94563b09e13cb7a64478fc406947a93cb34a7e05870fc8dcd48e23fd`.
   Real-model test execution is not a verified multilingual result receipt or a
   comparative performance claim.
6. All 25 exact generated archives must pass content inspection and extracted
   compilation, including an H100 CUDA-feature compilation. Full SDK, security,
   license, SBOM, and hosted-equivalent gates must bind the final clean SHA.
   Signed release and exact-SHA G8 closure remain unavailable until the later
   hosted release promotion.

25 publishable crates. `hyphae-native-embed-cpu` is in layer 6, depends on
`hyphae-native-catalog` and `hyphae-native-product`, and carries both default

on it with requirement `=4.0.0`. The executor crate and CLI must include their
source, README, license files, and third-party notices. The protocol crate
must include its shared minor-9 request fixture mirror. The package audit
checks every compile-time asset in generated crate contents; extracted package
verification patches all 25 packages locally and rejects an older registry
copy. Exact `=4.0.0` registry dry-runs of upper layers may be blocked until
earlier layers appear in crates.io; that is publication-order behavior rather
than source failure.

## Exact candidate package commands

The candidate version is deliberately absent from crates.io, so the exact local
dry run packages the complete closure together and then checks the extracted
archives with local patches. Independent `cargo publish --dry-run` calls would
incorrectly require unpublished `=4.0.0` dependencies from the live registry.

```bash
export CARGO_TARGET_DIR=/opt/dlami/nvme/hyphae-targets/12-release-final
cargo package --locked --no-verify \
  -p hyphae-core -p hyphae-native-types \
  -p hyphae-native-ann -p hyphae-native-catalog -p hyphae-native-mvcc \
  -p hyphae-native-pages -p hyphae-native-records -p hyphae-native-wal \
  -p hyphae-query -p hyphae-contracts -p hyphae-native-blobs \
  -p hyphae-native-btree -p hyphae-native-manifest -p hyphae-retrieval \
  -p hyphae-native-runtime -p hyphae-storage -p hyphae-engine \
  -p hyphae-native-product -p hyphae-native-embed-cpu \
  -p hyphae-native-protocol -p hyphae-client \
  -p hyphae-native-daemon -p hyphae-server -p hyphae-cli \
  -p hyphae-pliegors --target-dir "$CARGO_TARGET_DIR/package-dry-run"
python3 tools/check_crate_packages.py
python3 tools/verify_crate_packages.py
```

The commands produced and audited all 25 `4.0.0` archives on the exact H100;
the extracted-package workspace build passed. Live publication remains the
protected workflow's one-package-at-a-time
`cargo publish --locked -p "$package"` loop after every preceding layer is
visible; none of these local commands grants publication authority.
