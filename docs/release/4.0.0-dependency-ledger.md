## Exact candidate package commands

The candidate version is deliberately absent from crates.io, so the exact local
dry run packages the complete closure together and then checks the extracted
archives with local patches. Independent `cargo publish --dry-run` calls would
incorrectly require unpublished `=4.0.0` dependencies from the live registry.

```bash
export CARGO_TARGET_DIR=/opt/dlami/nvme/hyphae-targets/12-release-final
cargo package --locked --no-verify \
  -p hyphae-core -p hyphae-native-types \
  -p hyphae-native-ann -p hyphae-native-catalog -p hyphae-native-mvcc \
  -p hyphae-native-pages -p hyphae-native-records -p hyphae-native-wal \
  -p hyphae-query -p hyphae-contracts -p hyphae-native-blobs \
  -p hyphae-native-btree -p hyphae-native-manifest -p hyphae-retrieval \
  -p hyphae-native-runtime -p hyphae-storage -p hyphae-engine \
  -p hyphae-native-product -p hyphae-native-embed-cpu \
  -p hyphae-native-protocol -p hyphae-client \
  -p hyphae-native-daemon -p hyphae-server -p hyphae-cli \
  -p hyphae-pliegors --target-dir "$CARGO_TARGET_DIR/package-dry-run"
python3 tools/check_crate_packages.py
python3 tools/verify_crate_packages.py
```

The commands produced and audited all 25 `4.0.0` archives on the exact H100;
the extracted-package workspace build passed. Live publication remains the
protected workflow's one-package-at-a-time
`cargo publish --locked -p "$package"` loop after every preceding layer is
visible; none of these local commands grants publication authority.
