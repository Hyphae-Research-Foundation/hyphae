The tagged manifests contained a versioned development-dependency cycle
between `hyphae-client` and `hyphae-server`. Cargo correctly refused to create
a minimized lockfile before both versions existed. To preserve the immutable
tag, `hyphae-native-daemon` was published first, then Cargo produced the
`hyphae-client` archive with `--exclude-lockfile`. That archive retained the
normalized manifest, `Cargo.toml.orig`, and `.cargo_vcs_info.json` bound to
`e88f2ea2c3455a393e3ac0cd69e25486cc26888e`; it was uploaded through Cargo's
documented registry Web API. Its registry, downloaded, and local checksums are
identical. `hyphae-server` and the remaining packages then used ordinary
`cargo publish --locked`. The post-release manifest and package-audit changes
remove this cycle for later releases; they do not alter version `1.1.0`.

## Consumer verification

A clean `cargo install hyphae-cli --version 1.1.0 --locked` completed from
crates.io. The installed binary reported product `hyphae`, engine `1.1.0`, API
`v1`, disk format `2`, native directory format `1`, and product API version
`1`.

A separate temporary Rust application with exact dependencies on
`hyphae-engine = "=1.1.0"`, `hyphae-query = "=1.1.0"`, and
`hyphae-native-product = "=1.1.0"` generated a fresh lockfile and built with
`cargo build --locked`.

docs.rs accepted every library package. `hyphae-cli` is binary-only and does
not have a library-documentation build.
