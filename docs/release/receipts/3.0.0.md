## Consumer verification

A clean `cargo install hyphae-cli --version 3.0.0 --locked` completed from
crates.io on 2026-09-04. The installed binary reported product `hyphae`,
engine `3.0.0`, API `v1`, disk format `2`, native directory format `1`, and
product API version `1`.

A separate temporary Rust application with exact dependencies on
`hyphae-engine = "=3.0.0"`, `hyphae-query = "=3.0.0"`, and
`hyphae-native-product = "=3.0.0"` generated a fresh lockfile and built with
`cargo build --locked`.

docs.rs had documented `hyphae-core 3.0.0` and queued the remaining library
packages at the time of writing. `hyphae-cli` is binary-only and does not have
a library-documentation build.

## Registry drift closed on the way

The `main` push run for the first 3.0.0 merge (`95872a65…`, PR #261) failed
`Release readiness` because `tinyvec 1.13.0`, published the same day, does not
compile and three gates resolved dependencies against the live index instead
of a lockfile: the SemVer comparison (placeholder projects inside
`cargo-semver-checks`), the packaged-crate verification workspace, and the
`cargo-audit` install. PR #262 documents each crate from its own lockfile for
the SemVer gate, seeds the verification workspace with the workspace
`Cargo.lock` and rejects any registry version the lockfile does not name,
installs `cargo-audit` from its own lockfile, and retries `npm audit` only when
the advisories endpoint itself is unavailable. Its merge commit is the
publication source above.

## Distribution boundary

The TypeScript and Python clients and the JavaScript framework integrations
remain source-only in this release. Their `3.0.0` source manifests and local
package audits do not constitute npm or PyPI publication.
