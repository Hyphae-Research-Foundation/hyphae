# Hyphae 1.2.0 operator and agent experience plan

Status: implementation complete; release publication pending

Hyphae 1.2.0 turns the 1.1.0 native engine into an installable, secure operator
and agent experience without introducing a second data, identity, or execution
authority. Every surface consumes the same native product operations and the
same durable RBAC decision.

This program shares one release candidate with the
[1.2.0 relicensing plan](1.2.0-relicensing.md). Relicensing cannot bypass a
functional gate, and functional completion cannot publish under inconsistent
license authorities.

## Outcomes

1. Durable principals, roles, scoped grants, API keys, revocation, rotation,
   owner recovery, migration, and bounded security audit.
2. One Ratatui console for SQL, structures, search, catalog, health, telemetry,
   maintenance, backups, sessions, and redacted security administration.
3. One versioned MCP server packaged for both Claude Code and Codex, with
   identical tool schemas and permission behavior.
4. A typed Python client published to PyPI with embedded/local and remote
   transports, sync and async APIs, and wheel/sdist provenance.
5. Exact-source Linux, macOS, and Windows receipts followed by the 1.2.0
   crates, PyPI, plugin, and binary release.

## Delivery sequence

### P0 — contract and threat model

- Accept the RBAC/API-key ADR, threat model, operation matrix, key grammar,
  scope semantics, finite limits, bootstrap, migration, recovery, and audit
  contracts.
- Make CI reject a new product operation without an explicit permission row.
- Freeze release gates and negative evidence before implementation claims.

Exit evidence: static checker and mutation fixtures pass, and the contract is
now marked `passed` after the implementation and hosted-equivalent matrices
closed.

### P1 — native security authority

- Store principals, custom roles, assignments, key verifiers, epochs, and audit
  events in canonical bytes committed by the native WAL.
- Enforce parsed SQL classes and stable catalog-object scopes at the product
  dispatcher, including prepared execution and transaction commit.
- Implement offline owner bootstrap/recovery, legacy-bearer migration,
  key create/rotate/revoke/expiry, and session reauthorization.
- Provide secret-safe CLI commands; secrets use new restricted files and never
  argv, JSON output, logs, telemetry, or the TUI.

Exit: crash injection and reopen tests for every security mutation; embedded,
local daemon, HTTP, CLI, and SDK decisions are byte-for-byte equivalent.

### P2 — Ratatui console

- Add `hyphae console --data-dir …` with accessible keyboard navigation,
  compact/narrow layouts, mouse-free operation, and deterministic rendering.
- Views: overview, SQL workbench, keyspace browser, search explorer, catalog,
  transactions, telemetry, maintenance/backups, and security.
- Use the public product client only. The console may explain an authorization
  denial but cannot bypass or synthesize authority.
- Bound history, result rows, event rate, memory, query time, and rendering
  work; the console applies a 30-second cooperative request deadline and
  bounded-loop cancellation checkpoints. This is not a universal latency or
  durability bound. Redact credentials and record contents from diagnostics by
  default.

Exit: golden terminal snapshots at 80×24, 120×36, and 200×60; scripted keyboard
flows; slow-terminal/backpressure tests; Linux/macOS/Windows receipts.

### P3 — MCP and agent plugins

- Promote the existing MCP adapter to the native product contract with
  versioned tool schemas, bounded pagination, cancellation, idempotency, and
  structured errors.
- Ship Claude Code and Codex manifests/configuration generators around the same
  stdio server; do not fork tool implementations.
- Default agent credentials to the narrow `developer` or `reader` role and
  document explicit escalation for maintenance/security operations.
- Add prompt-injection fixtures proving tool input cannot widen key authority
  or reveal secrets.

Exit: both hosts pass the same conformance corpus and negative authorization
matrix against one exact Hyphae commit.

### P4 — Python/PyPI

- Ship `hyphae` with typed models, sync/async clients, context-managed embedded
  and remote sessions, streaming pagination, transaction helpers, and stable
  error codes.
- Build reproducible sdist and abi3 wheels where native embedding is supported;
  otherwise provide the public local/HTTP client without silently downloading
  a server.
- Run Python-version, OS, cancellation, reconnect, key-redaction, and live
  conformance matrices.

Exit: TestPyPI install/verify receipt, then PyPI publication bound to the exact
1.2.0 source tag and SBOM/provenance.

### P5 — hardening and release

- Random-model RBAC/scope tests, secret canaries, malformed protocol fuzzing,
  crash/recovery matrices, dependency/license audit, and performance budgets.
- Update docs, examples, completions, install packages, plugin manifests, and
  registry metadata from exact generated authorities.
- Close the relicensing preflight, coherent-change, and deterministic
  verification gates on the same exact candidate.
- Publish only after every required exact-SHA gate is terminal green.
- Require the exact-SHA `Security hard-kill aggregate` and `MCP real hosts`
  checks and independently validated named artifacts in the external registry
  publication authority; `Release readiness` also depends on both jobs.

Exit: annotated `v1.2.0`, signed packages and provenance, crates.io/PyPI/plugin
receipts, GitHub Release, and only `main` retained.

## Non-negotiable gates

- No universal latency claim; transport, execution, queueing, and durability
  remain separately measured.
- No hosted identity dependency, external database, sidecar, or cloud-only
  requirement.
- Unknown permissions, roles, scopes, key versions, operation variants, and
  durable states deny by default.
- An API key never widens its principal; role/scope/permission intersection is
  recomputed at the current epoch.
- No release or registry publication while an authority is open or source and
  artifact identities differ.

## Current checkpoint

The requested 1.2 implementation slices are closed. SQL direct execution,
`EXPLAIN`, prepared reads, and staged transactional SQL reuse one
catalog-version-bound authorization binding, including secondary-index and
foreign-key dependencies. Raw scalar Get/Set/TTL resolves the strict
lineage-bound durable default-keyspace identity. Managed catalog listing uses
the `HYCAT007` scope index and a MAC-bound continuation that reveals neither a
physical cursor nor invisible traversal accounting.

The managed key lifecycle is public and central: issue and rotate are
two-phase, one-time secret deliveries that stay inactive until client-side
restricted-file synchronization and explicit activation; abort and revoke are
idempotent product operations. Offline owner `inspect`, `recover`, `resume`, and
`abort-pending` validate OS ownership, path identity, permissions/ACLs, and
exact pending provenance. The one-minor legacy-bearer bridge is implemented
only for Native HTTP with terminal durable revocation; UDS/named-pipe never
accepts it, owner recovery revokes it, and the 1.3 compatibility gate rejects
an enabled bridge.

The bounded Ratatui workspaces for structures, search, catalog, backups,
operations/transactions, and proofs use only public `ProductOperation` values.
They retain one active operation and one response, apply explicit limits and
confirmations, and support cooperative cancellation/backpressure. Security
views remain intentionally read-only and secret-free.

MCP remains a three-tool read-only surface with one active call, bounded output,
`notifications/cancelled`, and no unbounded response queue. Codex 0.147.0 and
Claude Code 2.1.233 pass the same four-case corpus through their real host
control planes without a model call. The security crash inventory covers 21
public mutating `ProductOperation` paths and five exact public offline
transitions: 182 injected boundary/reopen cases and the same 182 real process
hard-kill cases. Each child parks in the exact commit hook before unwinding;
the parent requires signal 9. This is process-crash evidence, not power-loss
evidence.

Relicensing is effective in the integration tree: software and normative
specifications are Apache-2.0, narrative documentation remains CC-BY-SA-4.0,
and DCO 1.1 governs new inbound contributions. Local workspace tests, Clippy,
Rustdoc, SDK suites, license/dependency checks, transition checks, and the real
MCP-host receipts pass. Version/tag/package publication remains deliberately
unperformed; the next action is hosted validation of the committed exact tree,
followed by the separately authorized 1.2.0 release sequence.
